# 给美术标签绑定资源 SVN

美术在资源提交网站（`https://artrestrans.eros.nie.netease.com`）上传资源后，群里会收到“……已于 `art_…` 成功上传 N 份新资源……请策划告知程序为该标签或对应总单绑定svn”的通知。用户要求给这个标签绑定 SVN、查标签绑了什么时读取本文件。手工做法是在网站「标签」页选标签、添加一行资源地址、点「绑定」；脚本 `scripts/art_bind.py` 做同样的事。

## 流程

1. **查现状（只读）**：

   ```text
   python "<skill>/scripts/art_bind.py" show --tag "<标签>"
   python "<skill>/scripts/art_bind.py" show --text-file <通知原文.txt>
   ```

   标签是通知里 `art` 开头的那一整行（可能很长，带全角括号，原样使用）。手上是通知原文时存成 UTF-8 文件用 `--text-file`，脚本从“已于 … 成功上传”之间或 `res_copy/<标签>/` 路径里取标签。

2. **预览**：

   ```text
   python "<skill>/scripts/art_bind.py" bind --tag "<标签>" --root "<项目>"
   ```

   资源地址取 `<项目>/../_test` 资源工作副本的地址（带 `_test`，和手工绑定填的一样）；要绑别的地址时用 `--svn <地址>` 代替 `--root`。输出的 `will_bind` 是将要提交的整份列表。

3. **提交**：把标签、要绑的地址和 `will_bind` 告诉用户，**用户确认后**在同一命令后加 `--apply`。这会改平台上的配置：之后这个标签的资源会进这个地址，绑错了要到网站上解绑。

## 规则

- 平台的绑定是**整份列表覆盖**：标签的绑定里资源地址和 popo 群号混在一起（群号是策划的审核群，美术通知发到那里；它不是开发群，不能拿来判断该绑哪个分支）。脚本先读现有列表、在后面追加、再整份提交，原有的每一项都保留。不要自己拼列表调接口。
- 已经绑过同一个地址时不提交，`message` 说明没有改动。
- 地址必须在资源仓库下（`svn-xyq.gz.netease.com/svn/products/xy1/share[/patch]/…` 或 `…/svn/xyqs/share[/patch]/…`），否则脚本直接拒绝（平台也会报“非法格式”）。
- 标签里的单号（`art_<单号>_…`）是美术需求单，它的总单是美术自己的总单，和程序的开发分支、总单没有对应关系；**绑到哪个分支由用户决定**，不要按单号推断。
- 解绑、按总单绑定脚本不做，到网站上操作。
- 登录用用户级配置里的 CORP 账号（见 `corp-login.md`），绑定后平台上的“最新绑定者”是这个账号。

## 输出

一个 JSON 对象，字段固定（不适用的为 null 或空列表）：`action`、`applied`（是否提交过）、`changed`（提交并读回核对通过）、`tag`、`svn`（要绑的地址）、`bound`（现有的整份列表；提交后是读回的）、`svns`、`groups`（列表里的资源地址和 popo 群号）、`binder`（最新绑定者）、`need_bind`（平台是否还在等绑定）、`art_svn`、`uploader`、`mod_time`、`will_bind`（预览时将提交的列表）、`message`、`errors`。

退出码：0 成功；1 失败且平台没有改；2 已提交但读回的列表核对不上（`errors` 里写了缺哪一项，请用户到网站上核对，不要重复提交）。
