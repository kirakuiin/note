# 开发分支

只有用户明确要求创建开发分支或把分支检出到本地时，才读取并执行本流程。脚本 `scripts/branch.py` 的路径按 skill 安装目录确定，不依赖当前工作目录。可选配置 `branches_root` 只供 `reusable` 和 `checkout` 使用；`name` 和 `create` 不需要它。配置和缺省处理见 `workspace-management.md`「配置」。

若 `branches_root` 未配置且命令没有传 `--root`，脚本会停止并提示设置命令；如果能从 Cursor 或 VS Code 的 `MHCoder.branchesBaseDir` 读取旧值，会把它作为建议显示。向用户询问要使用的绝对路径，再由用户选择直接通过 `--root` 使用，或按 `workspace-management.md`「配置」保存为用户级配置；旧值只是建议，不自动写入。

运行脚本时保持当前会话工作目录，不要为调用脚本切换到 skill 目录或待复用目录：复用保护会根据当前目录识别会话正在使用的工作区，工作区级配置也从当前目录读取。

## 创建分支

1. 用户描述用途后，将其改写为简短英文小写用途，最多两个单词，用下划线连接，例如“七夕活动”写成 `qixi`，“法术强化”写成 `magic_buff`。用途只接受 `^[a-z][a-z0-9]*(_[a-z0-9]+)?$`。
2. 先运行只读命名预览：

   ```text
   python "<skill>/scripts/branch.py" name --purpose <用途>
   ```

   脚本从用户级 `openid_username` 的邮箱前缀推断缩写：去掉末尾数字，按标准拼音音节切分并取首字母；取音节数最少的切分，数量相同时优先让前面的音节更长。无法切分时保留原邮箱前缀（含末尾数字）。

3. 使用创建预览查看完整分支名、根基、作者、接口参数、脚本和资源 URL：

   ```text
   python "<skill>/scripts/branch.py" create --purpose <用途> [--base <根基>] [--no-res]
   ```

   根基默认 `release`，用户指定时原样使用。默认同时创建脚本和资源分支；用户明确不需要资源分支时加 `--no-res`。预览会用只读 `svn info` 检查脚本 URL 是否已存在。

4. 把预览中的完整分支名、根基、作者、资源分支选择和 URL 告诉用户，用一个问题同时确认后续范围（选项：创建、检出并初始化工作区（推荐）／创建并检出／只创建；用户本轮已说明的直接采用）。用户明确确认后，在相同命令中加 `--branch <预览中的完整分支名> --apply`。分支名含当天日期，跨日后重新计算的名称会变，脚本发现与 `--branch` 不一致时拒绝创建，此时重新预览并确认。脚本先记下服务端已有的同名记录，请求后只看新出现的记录，结果会是 `created`、`failed` 或 `timeout`；超时后稍后检出时会再次核实。
5. 创建成功且用户在第 4 步选了检出时，直接进入「检出到本地」，不再询问；该流程的检出预览确认仍要做（会改名、删除目录）。

## 检出到本地

1. 单独检出时由用户提供分支名。先运行 `reusable --root <总目录>` 查看候选目录（省略 `--root` 时读取 `branches_root`）。没有候选时直接新建，不询问；有候选时新建还是复用由用户决定，选择复用时请用户从候选中指定目录，并提醒先关闭打开该目录的 IDE 窗口。
2. 先预览检出操作：

   ```text
   python "<skill>/scripts/branch.py" checkout --branch <分支名> [--root <总目录>] [--reuse <目录名或绝对路径>]
   ```

   开发分支优先在近期分支记录中精确匹配，再按分支名中的年份构造 URL；随后逐个用 `svn info` 核实脚本 URL 和 `_test`、`_testhd` 资源 URL。脚本分支不存在会停止；不存在的资源子分支会跳过并警告。复用目录必须与 `reusable` 列出的候选同一标准：是总目录的直接子目录（普通目录），含 `mhimage` SVN 工作副本，且不能是当前会话目录或它的祖先目录。复用前检查各工作副本的状态（不含外链）：有本地修改，或有未纳入版本控制的文件（`?`，switch 会把它们原样带进新分支）都会拒绝，并列出这些文件，由用户自己处理；被忽略的文件（如构建产物）不影响复用。资源工作副本很大时状态检查可能较慢；超时会单独报告“SVN 命令超时”，不是 svn 不可用。

   周期分支（`<类型>_<yyyy>_<mm>_<dd>`，如 `zlp_2026_10_13`）只能检出，不能创建。脚本在 `<年份>_ship` 下；资源按类型共用 xyq-res 仓库的固定目录，只检出 `_test`，对应关系见 `branch.py` 的 `PERIODIC_RESOURCES`；release 只检出 `mhimage`。复用目录的资源子目录与目标不在同一仓库（开发分支和周期分支互相复用时都会发生）时无法 switch：预览会显示先把它改名为 `<目录>.old-<时间>` 挪开、检出新目录，最后删除挪开的旧目录；时间在 `--apply` 时重新生成，实际改名后的路径以 `--apply` 结果中 `completed_steps` 的 `rename ... -> ...` 命令为准。要求旧目录完全干净（含未纳管、被忽略的文件）；最后删除前再检查一次，状态无法检查、不干净或删除失败时保留并在结果中给出路径。复用目录中本次不检出的资源子目录（如 release 下的旧 `_test`）保持原样，预览会警告。

3. 检查预览中的目录、URL、改名、删除和 SVN 命令。请用户确认时一并问检出后是否初始化工作区（已在创建时选过或本轮已说明的不再问）。用户明确确认后，在同一命令中加 `--apply`。脚本检出 `mhimage` 可能需要几分钟，运行时应放到后台并等待完成；失败时脚本会报告完成和剩余步骤，不会自动回滚。跨仓库替换中途失败（如挪开后的检出失败）时，原位置可能留下半检出的目录：不要删除它，先把它改名挪开（例如 `<目录>.failed-<时间>`），再把 `.old-` 目录改回原名，然后用 `--reuse <分支名>`（复用目录此时已改名为目标目录）重跑预览。挪开的半成品目录和剩余步骤里的 `remove` 都不由 agent 删除：告诉用户路径，由用户确认不再需要后自行删除。
4. 检出完成后，用户已选初始化的，按本 skill 的 `SKILL.md` 流程对 `<总目录>/<分支名>/mhimage` 执行初始化（`--root` 指向该目录），不再询问；用户级配置已齐全时只需应用。
