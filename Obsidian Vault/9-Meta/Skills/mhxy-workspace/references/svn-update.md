# SVN 更新

仅在用户明确要求更新 SVN 工作副本时读取并执行。初始化、更新 skill 配置、普通开发或只读查看 SVN 状态均不触发。仅使用 SVN，不依赖其他 skill 或其脚本。

## 范围与预检

- 用 `svn info` 确认用户指定目录的工作副本根、实际仓库 URL 和当前版本，用 `svn status` 检查本地状态；不靠本地文件夹名称判断分支。
- 默认只更新用户指定的代码工作副本。对其上层的 `../_test`，先询问是否一并更新，未经明确同意不更新；用户本次已经明确包含它时不重复询问。不存在则报告跳过，不自动 checkout。不自动纳入引擎、全局资源或其他工作副本。
- 保留本地修改和未版本控制文件；本地修改本身不等于冲突，不自动 revert、清理或覆盖。已有冲突先报告并停止受影响工作副本的更新；锁定、缺失或阻挡文件按实际错误报告，不自动 cleanup、resolve 或删除。

## 选择目标

- **周期分支**：实际代码 URL 符合 `wzimage/branchs/<年份>_ship/<类型>_YYYY_MM_DD`（类型见 `workspace.py` 的 `PERIODIC_TYPES`）时，尽量更新到下一个维护周。context 输出的 `branch.kind` 按同一规则判定（`workspace.py` 的 `PERIODIC_BRANCH`）。
  - 目标日期为本地日期之后最近的周二；周二当天取下周二，跨年使用目标日期所属年份。
  - 用 `svn list`／`svn info` 确认真实远端分支，保持仓库与前缀不变；不能只拼接 URL 就执行。优先选择目标日期的分支，存在则用 `svn switch` 切换并更新；已经在目标 URL 时直接 `svn update`。
  - 目标分支尚未发布时，在同前缀已发布分支中选择不晚于目标日期且不早于当前分支日期的最新分支；没有更新候选则保持当前 URL 执行 `svn update`，明确说明未到达目标维护周。不自动退回旧周或跳到更远的周。无法可靠列出远端时报告原因，不把网络／权限失败当作分支不存在。
- **其他工作副本**：包括 trunk、开发分支及不匹配上述规则的目录，保持当前 URL，直接 `svn update`；不套用维护周规则。
- 用户同意更新的 `../_test` 保持其当前 URL 执行 `svn update`，不根据代码日期切换资源分支。资源目录必须是独立可用的工作副本；否则报告，不向上扩大更新范围。

执行前简述实际路径、当前与目标分支、资源是否已获授权。用户已明确要求更新时不另设固定的“回复 1”审批；有歧义或将影响未授权目录时先澄清。周期切换若涉及明显不兼容的本地修改，先说明风险并确认处理方式，不自行丢弃修改。

## 执行结果与外链错误

- 每次 update／switch 后结合命令输出、`svn info` 和 `svn status` 核对实际 URL／版本及文本、属性、树冲突；不能只按退出码判断，也不能把“无冲突”等同于“全部更新成功”。
- 有冲突时报告具体路径并停止受影响部分，不自动解决或回滚。没有冲突时，允许本轮以告警或部分完成结束；外链（`svn:externals`）失败不必使代码主工作副本的已完成更新作废，也不强制重试修复外链。
- 区分主工作副本、失败外链和独立资源目录。即使命令非零退出，若确认只是外链失败，可继续用户已授权且不依赖该外链的独立更新；主工作副本未达到目标时明确记录，不能报成成功。状态检查本身失败时标记“冲突状态未确认”。
- 报告最终分支／版本、冲突检查结果、失败路径与简短原因，以及资源更新或跳过情况。未执行、部分完成、成功分别说明；不隐瞒错误，也不承诺跨工作副本原子更新。不执行提交、分支创建或删除。
