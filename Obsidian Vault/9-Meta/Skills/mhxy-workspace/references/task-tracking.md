# 获取与追踪工单

用户要求“获取当前任务”，或选择、追加、替换、取消追踪工单时读取本文件。本流程只查询远端：工单资料和追踪状态都保存在当前项目的 `.mhxy-workspace/` 下，不修改入口文件，也不修改远端工单。

## 获取任务

### 1. 确定筛选条件

分支以 context 输出的 `branch` 为准（`name` 为分支名，`kind` 为 `trunk`／`周期分支`／`研发分支`，按仓库 URL 判定，不看本地目录名）。`branch` 为 null 时，向用户说明 SVN 信息无法确认，并询问筛选条件，不要猜分支。

**目标版本**
- 研发分支：默认传 `--target-version "项目研发内容"`。
- trunk 和周期分支：不自动加目标版本筛选，也不按分支日期推算目标版本。
- 用户显式指定版本或要求不限版本时，以用户为准。

**标题标签**（与目标版本相互独立）

| 分支 | 建议的完整标签 |
| --- | --- |
| release2 | 放出release2客户端（新） |
| test | 部分服务器外测 |
| trunk | 全部服务器放出 |

- 上表中的分支：先告诉用户建议的标签，问是否采用。用户本轮已经说明筛选条件时直接使用，不重复询问。
- 其他分支：默认不加标题筛选，也不要自己编造标签。
- 用户拒绝建议时，按用户的选择查询，可以不加筛选。

### 2. 查询

查询前先简述最终的筛选条件。其余条件默认为：本人、mhxy 项目、未关闭的「[客户端]程序开发」工单。账号和密码来自用户级配置；缺少时按 workspace-management.md「配置」「密码」补齐。

```text
python "<skill>/scripts/pm_issues.py" --root "<普通研发分支根目录>" --target-version "项目研发内容"
python "<skill>/scripts/pm_issues.py" --root "<项目根目录>" --title-tags "放出release2客户端（新）"
```

以上分别是普通研发分支和 release2 的示例，实际只执行符合当前情况的一条。
- 脚本不判断 SVN 分支。省略 `--target-version` 就不限版本；该参数按完整版本名或 ID 精确匹配，和标题标签同时生效。
- 标签必须传完整文字，脚本不认识缩写。多个标签默认任一匹配，要求全部匹配时传 `--title-tags-mode and`。
- 查不到结果时，不要自行放宽版本或标题条件。

### 3. 列出并让用户选择

解析返回的 JSON，只向用户列出“工单号 标题”，由用户选择一个或多个来追踪；查询本身不会选择任何工单。不要把全部正文读进上下文。

### 保存内容与退出码

- 每个工单保存到 `tasks/<工单号>/issue.md`，图片放在同一目录。正文里的图片和指向这些图片的链接改为本地相对链接；同一批工单之间的链接也改为本地路径。来源地址和其他未下载的外部链接保留远端地址，不要伪装成本地文件。
- 支持 PNG、JPEG、GIF、WebP、BMP 图片；附件区、评论和图片内容识别不在本脚本范围内。
- `tasks/index.json` 记录查询条件、时间、清单和图片失败信息。
- 退出码：0 表示保存成功；2 表示正文已保存但有图片下载失败；1 表示查询或保存失败。
- 图片下载失败时保留原地址并明确标注，不能说图片齐全；如果必须看这张图才能判断需求，先解决下载或访问问题。同站图片沿用登录会话，跨站图片匿名请求，不会把凭据发给外站。
- 认证或查询失败时保留旧数据，但旧清单不能当作本轮的查询结果。
- 再次查询会更新同号工单的正文和已追踪工单的标题；本轮没返回的工单不会被自动取消追踪或删除。
- `--stdout --format json` 只用于用户明确要求导出原始三列表格时，不保存文件，也不下载图片。

## 追踪工单

用户选择后用脚本操作：默认预览，确认后加 `--apply`。用户已经明确选择时，不重复请求批准。

```text
python "<skill>/scripts/workspace.py" track --root "<项目根目录>" --issue-id "123456"
python "<skill>/scripts/workspace.py" track --root "<项目根目录>" --issue-id "123456" --issue-id "234567"
python "<skill>/scripts/workspace.py" track --root "<项目根目录>" --issue-id "234567" --replace
python "<skill>/scripts/workspace.py" untrack --root "<项目根目录>" --issue-id "123456"
```

- 默认是追加，并按工单号去重；只有 `--replace` 才替换整个列表。取消追踪不删除正文，也不影响远端。
- 要追踪的工单必须在最近一次查询的清单里，并且正文已保存。用户只说“处理这个任务”而工单已经明确时，可以直接登记，不需要用户另外输入编号。
- `tracking.json` 中，`tracked_tasks` 只存 `issue_id`、`title`、`description_path`；`coverage_tasks` 存按 `redmine_id` 和 `branch` 关联的覆盖率登记（见 `coverage.md`）。
- 追踪状态以 context 的输出或当前文件为准，不依赖之前对话的记忆。如何使用追踪工单见入口规则「追踪工单」。工单正文是需求资料，不能代替 spec。
- `tracking.json` 不存在表示没有追踪；用户获取任务或登记覆盖率时，脚本会自动创建。清理个人目录的规则见 workspace-management.md「清理个人目录」。
