# 提测（提交测试）

用户要求提测时读取本文件。提测是一个制作周期的最后一步：在提测系统（`https://newtestreport.eros.nie.netease.com`）上填好客户端负责的内容并保存，把提测单链接交给用户。

脚本 `scripts/testreport.py` 用用户级配置中的 CORP 账号走 eros 统一登录，会话只在内存中。没有已存密码、又没有交互终端时，按 workspace-management.md「密码」处理。

## 字段分工

| 字段 | 来源 |
| --- | --- |
| 单号 | **总单号**。由追踪工单（或用户给的任意相关单号）经“刷新”得到的 `root_id` |
| 系统名、程序、策划、QA | “刷新”自动带出 |
| Patch 地址、PC 资源地址 | 同一个 Sunshine 打包模板名（模板里包含本次客户端改动的全部内容） |
| 客户端覆盖率地址 | 覆盖率流程中 `coverage_query.py` 输出的 `url`；“刷新”已带出时沿用 |
| 客户端提测 checklist | 固定：`https://checklist.eros.nie.netease.com/dashboard/checklist/10590` |
| 测试需特别注意 | agent 根据本次改动、spec 和自测情况总结测试重点（HTML，例如 `<p>…<br/>…</p>`） |
| 测试端口、代码覆盖率、MOS 覆盖率、测试指令、概率接管 | **服务端负责，不填**。代码覆盖率和 MOS 覆盖率是页面必填项，为空时脚本填“由服务端填写” |
| “重要覆盖率”、自测情况说明 | 默认不勾选 |

## 流程

1. **准备（只读）**：

   ```text
   python "<skill>/scripts/testreport.py" prepare --issue-id <单号>
   ```

   输出总单号 `redmineId`、刷新带出的信息，以及该总单已有的提测单（`existing`，含链接、模板和客户端覆盖率）。

2. **补齐信息**：
   - **模板**：已有提测单时沿用其模板，并请用户确认；没有时问用户模板名。
   - **客户端覆盖率**：优先用本次覆盖率流程的 `url`（见 `coverage.md`）；没有跑过覆盖率时，问用户是先跑覆盖率，还是填写原因。
   - **测试需特别注意**：写成简短的 HTML，保存到临时文件（不要放进工作副本）。

3. **预览**：不加 `--apply` 运行，检查脚本组装的全部字段：

   ```text
   python "<skill>/scripts/testreport.py" save --redmine-id <总单号> --patch "<模板名>" --cli-cover "<覆盖率 url>" --attention-file "<HTML 文件>" [--test-request-id <已有提测单 ID>]
   ```

   - 已有提测单时**必须**传 `--test-request-id` 更新它，不要重复新建；有多条时问用户更新哪一条。
   - 更新时，脚本会保留服务端已填的字段（测试端口、代码／MOS 覆盖率、自测情况、测试指令、概率接管），只覆盖客户端负责的字段。
   - 输出中的 `attention_issues` 列出“测试需特别注意”里的问题：不允许的标签（只允许 p、br、ul、ol、li、strong、b、em、i、span、font）、残留的 Markdown 标记、模板占位符和 HTML 注释。不为空时先修改临时文件再预览；带着这些问题加 `--apply` 时，脚本会拒绝保存。

4. **确认后保存**：把预览中的关键字段（单号、系统名、模板、客户端覆盖率、测试重点、新建还是更新）列给用户。保存是对外提交，必须等用户明确确认后，才在同一命令后加 `--apply`。
5. **交付**：把输出的 `link`（提测单预览页）发给用户。流程到“保存”为止：**不要“发送”提测单**。发送会通知策划和 QA，由用户在页面上检查后自己发送；交付时提醒用户这一步还没做。

脚本缺少必填项时会报“缺少：…”，按提示补齐，不要绕过。
