# 开发流程改造：Codex 委派与人工决策点

日期：2026-10-15　版本：0.3.20

## 目标

需要人做决策的地方只保留必要的几处，其余步骤自动完成。Claude 主会话把调查、review、真机自检交给 Codex CLI，尽量节省 Claude token。

## 流程

1. 讨论需求。读代码交给 Codex 调查。只有真正需要用户决策的事项才用 grilling 提问；讨论结束时给出方案流程图，请用户确认。
2. 写 spec：只用于留档，不需要用户确认。
3. 主线程写代码。
4. Codex review：主线程逐条判断意见，采纳的就修改；最多 3 轮。第 2 轮起沿用同一个会话。只有真正重要的分歧才交给用户。通过时记录 review 指纹。
5. 真机自检：用户先开好客户端、确认设备，再交给 Codex 执行。默认包含改动执行检查（逐行确认改动被执行到）。发现缺陷就回到第 3 步。
6. 交付：先做提交前自检，再附提交说明，由用户确认提交。

小改动（判断标准见 engineering-principles「编码前先设计」）不写 spec，不做 Codex review。

## 委派方式

| 主会话 | 方式 |
| --- | --- |
| Claude | `scripts/codex_cli.py`：固定 `gpt-6.1-sol` + `high`；任务分 investigate / review / test 三类；用 `run_in_background` 运行 `wait`，结束时收到通知 |
| Codex | 原生子代理，分别对应 investigator / reviewer / verifier 三个角色；传 `fork_turns="none"`，任务说明里禁止再派生子代理；不调用脚本 |

- 两种方式共用 `references/cli.md`（由 cli-testing.md 改名而来）中的任务模板和结果格式。
- 被调起的子 Codex 不得再委派：设置环境变量 `MHXY_CODEX_CHILD=1`，脚本检测到就拒绝启动；同时关闭 agents / multi_agent，并在任务说明里写明。
- 清掉继承来的 `CODEX_*` 环境变量（`CODEX_HOME` 保留）。
- `cli_testing.py` 中仍然需要的能力保留：设备锁、MCP 白名单、无输出超时。
- 一并修复旧脚本的问题：状态文件并发读写、`references` 被覆盖、`_worker` 可能重复启动、clean 与设备锁冲突。Codex 宿主专用的 `_worker` 和 `exec` + `notify` 删除。

## 删除或合并

- engineering-principles「独立设计流程」（设计子代理、主线程各出方案、核对模型 ID）：删除，由 Codex 调查加用户确认流程图代替。
- code-review.md 的同模型 Plan 子代理：改为 Codex review。审查清单、收敛条件、3 轮上限保留。
- exec-check：并入第 5 步作为默认方法，不再需要用户另外要求。
- svn-commit.md「交付时询问是否做改动执行检查」：删除。
- 画图规则：Claude 主会话用可视化组件，Codex 主会话用 Mermaid。

## precommit 新增检查

- Mock／追踪器残留：业务代码中新增的 monkey patch、`sys.settrace`、测试钩子。
- review 之后又改过的部分：用 `precommit.py --mark-reviewed` 记录各文件的 diff 指纹；自检时列出 `changed_since_review`，交给 Codex 只 review 这部分增量。
- 语法检查：项目编码检查工具没有覆盖时，才补充对改动 .py 的编译检查。

## 其他

- 梦幻西游代码定位经验和指令平台 `$$call` 格式从 Codex 全局 AGENTS.md 移入入口模板的「项目约定」。
- `track`、`coverage-task` 在未初始化的目录中也拒绝运行。

- 防递归保护在真实子 Codex 中生效。
