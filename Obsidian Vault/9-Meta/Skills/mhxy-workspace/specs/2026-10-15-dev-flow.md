# 开发流程改造：Codex 委派与人工决策点

日期：2026-10-15　版本：0.3.21

## 目标

在保证开发质量的前提下尽量节省 Claude token。只在必要的节点请用户决策，其余步骤自动完成。调查、review 和真机自检交给 Codex 执行。

## 流程

1. **讨论需求**：读代码的工作交给 Codex 调查。只有真正需要用户决策的事项才用 grilling 提问。讨论结束时给出方案流程图，请用户确认（迭代已有功能时，图中要区分现有流程和本次改动）。
2. **写 spec**：只用于留档，不需要用户确认。迭代已有功能时直接更新原 spec，并追加变更记录。
3. **编码**：主线程负责。可以按文件拆开的大改动，可以委派 Claude 子代理并行实现；主线程亲自读接口和交界处的 diff。
4. **Codex review**：主线程逐条判断意见，最多 3 轮，第 2 轮起沿用同一个会话。只有真正重要的分歧才交给用户。review 通过后记录指纹。
5. **真机自检**：用户先开好客户端、确认设备，再交给 Codex 执行。默认做改动执行检查；迭代时另加回归用例。
6. **交付**：先做提交前自检，再附提交说明，由用户确认提交。之后整理记忆。

小改动不写 spec，也不做 Codex review。

在第 2、4、6 步完成后，以及开始另一项功能之前，检查上下文占用：超过 50% 时写交接文件，并生成新会话便签。

## 委派方式

| 主会话 | 方式 |
| --- | --- |
| Claude | 使用 `scripts/codex_cli.py`，固定 `gpt-6.1-sol` + `high`，任务分 investigate / review / test 三类。investigate 可接入只读 MCP（codeviewer-mcp、expert_knowledge）。用 `run_in_background` 等待结果 |
| Codex | 使用原生子代理 investigator / reviewer / verifier，传 `fork_turns="none"`。设备锁通过 `codex_cli.py lock` / `release` 管理 |

- **规则来源**：调用规范见 `references/cli.md`；review 的信息、清单和定级见 `code-review.md`；会话交接、记忆整理和经验沉淀（仅 Claude）见 `session.md`。
- **子 Codex 的限制**：不得再委派（环境变量 `MHXY_CODEX_CHILD`，并关闭 multi_agent）；不执行主会话规则；不写业务代码。test 任务只写 `.mhxy-workspace` 内的指定目录。

## 提交

所有分支都用 `svn_commit.py` 提交，首行格式按分支类型校验。提交前自检会检查 Mock／追踪器残留，以及 review 通过后又改过的文件（文件级指纹，含属性值）。提交成功后，从指纹记录中移除已提交的文件。

## 验收

- 全部测试通过。
- 真实运行 investigate、review、`--resume`、防递归保护。
- 在真机上完成 Mock 与报错收集，并释放设备锁。
- 交接便签在 SVN 目录中直接打开原目录。
- 本次改动经过 Codex review。
