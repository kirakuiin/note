# 追踪工单的策划文档检出

日期：2026-11-17　版本：0.3.53

## 目标

追踪工单时，正文里的设计 SVN 链接（文件或目录）检出到工单目录的 `docs/`，生成 Markdown 版，issue.md 直接指向本地文件；之后每次获取任务时 `svn update` 并刷新 Markdown 版。用户 2026-11-17 确认：检出到工单下的 docs 目录，update 时也更新 md。

## 实现

- 新模块 `scripts/task_docs.py`（只依赖标准库）：
  - `svn_links`：识别 `(https?|svn)://svn*.netease.com/svn/...`，去掉末尾标点和斜杠、解码百分号，去重；忽略之前写入的策划文档小节。
  - `sync_docs(task_dir, text)`：正文链接加上 manifest 里已有的链接逐个同步；单个失败记入 failures，不影响其他链接。
    - 根目录一律 `checkout --depth empty`；文件链接 `svn update <文件>`；目录链接 `svn list -R --xml` 列文件，单个 ≤20 MB、累计 ≤200 MB 的用 `svn update --parents` 取，已有内容先 `svn update .`。
    - 传给 svn 的 URL 先百分号编码（实测直接传中文时 `svn list` 会被代码页误转，报 W160013）。
    - 同名目录对应不同 URL 时加 `-2` 等后缀；本地有修改的文件不更新，报失败。
  - `convert`：xlsx 自己解析（共享字符串、单元格、drawings 浮动图片、WPS `DISPIMG` 单元格图片）；docx/pptx/pdf/xls 有 markitdown 且 ≤10 MB 才转换；md/txt 直接用原件。生成文件头写源文件 sha256，未变化不重新生成。
  - `link_issue`：正文链接改成本地路径，末尾写入（替换）`<!-- task-docs:begin/end -->` 小节。
- `workspace.track_tasks`：非取消追踪时附带 `docs`。预览列出链接；`--apply` 调 `sync_docs` 并改写 issue.md。
- `pm_issues.save_issues`：对追踪中的工单调用 `sync_docs`，issue.md 随本轮一起落盘；输出新增 `docs`、`doc_failures`，有文档失败时 `status` 为 partial、退出码 2；`index.json` 记录 `doc_failures`。顺带修正：提前读取 tracking 后，变量 `old` 与循环内同名变量冲突，已改名为 `tracking_old`。

## 0.3.54：Markdown 版只转必要内容

用户 2026-11-17 补充：策划文档里客户端只关心玩法规则、UI 和美术需求；目录链接不需要转 md，只有单个文件才转。

- `SHEET_RULE`（玩法|规则|UI|界面|美术|表现|交互）：xlsx 只转工作表名命中的工作表，未命中的写在 Markdown 版开头和 issue.md 小节里（“只含：…；其余 N 张工作表见原件”）。一张都没命中时全部转换并注明。原件照常完整检出。869788 的 11 张工作表只转「玩法规则」「UI和美术需求」。
- 缓存哈希包含规则文本，规则调整后自动重新生成。
- 目录链接只检出（大小上限照旧），`documents` 为空，不生成 `_converted`。
