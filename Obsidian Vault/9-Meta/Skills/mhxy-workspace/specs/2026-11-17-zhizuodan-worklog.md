# 制作单提交后登记工时、推进度

日期：2026-11-17　版本：0.3.56

## 目标

用户 2026-11-17 定：研发分支上的制作单（目标版本「项目研发内容」）也在提交后登记工时；进度每次提交升一档（新建 → 10% → … → 90%，封顶 90%）；用户明确要求开始跑覆盖率时改为「测试中」。工单号必须由用户提供，提供后缓存在本地，之后不提供时默认用缓存。维护单流程不受影响。

## 设计

- **新增工作区级配置 `work_issue`**：`config/defaults.json` 加键，`workspace.validate_config` 校验为正整数（字符串或整数）或 null。用户指定制作单号时由 agent 用 `workspace.py config --set-local` 写入。
- **工单号来源**：只在研发分支上取，顺序：本次指定 → `work_issue` → 问用户。不从追踪工单、分支名或正文推断。
- **维护单不受影响的保证**：
  - 按 `pm_update.py` 只读查询的 `target_version` 区分，以「维护内容」结尾的一律走原有维护单约定，与分支和 `work_issue` 无关。
  - `work_issue` 只在研发分支读取；trunk、周期分支的工单号来源和 `finish #` 规则不变。
  - 不是制作单的号不写入缓存。
  - 合并提交、无人值守只按维护单约定处理，制作单约定不适用。
  - `pm_update.py`、`svn_commit.py`、`svn_merge.py`、`unattended.py` 不改。
- **不跳档、不回退**：先只读查询当前状态，再用 `--status <下一档> --status-from <当前状态>`；90% 及其他状态只登记工时。
- **覆盖率**：用户明确要求开始跑覆盖率时，从新建、10%–90%、代码审查改为测试中，不登记工时；只查询、补测、提交时不改。

## 文档

- `task-tracking.md`：新增「约定：制作单」，用法补制作单命令。
- `svn-commit.md`：研发分支工单号来源加 `work_issue`；交付内容第 4 项和「提交后更新工单」覆盖制作单。
- `coverage.md`：跑测流程加第 0 步。
- `workspace-management.md`：配置表加 `work_issue`。

## 验收

- `tests/test_patch.py` 新增 `test_work_issue_rules`：合法值、空串、0、带 #、非数字、负数、浮点、布尔、超长。
- 全量测试通过。
- 真实工单状态名（10%、测试中）在制作单上的可用性未在本次核实（只读预览被会话权限拦下），第一次实际登记时以预览结果为准。
