# Codex子代理配置与调整

## 背景

归档 Codex 用户级子代理安装指令及后续调整。原文保留在折叠附录，调整不回写原文。

## 调整意见

- **职责**：默认只读探查、检索和整理证据；设计与复杂实现由主代理负责，仅明确授权时允许简单机械批量修改。
- **派发**：由主代理按收益决定，最多 10 个子代理且遵守实际工具上限；每次明确禁止子代理继续派发。
- **背景**：每次显式传 `fork_turns="none"`，同时主动提供必要背景、领域知识、已确认事实、约束和资料位置。独立审查区分事实、假设与结论，不灌输主代理判断。
- **协作**：允许复用、补问和定向复核；主代理先做独立工作，需要结果时等待，单次超时不等于失败。
- **返回**：每轮通常只发一次最终答复，首行为 `complete` / `partial` / `blocked`；仅返回精炼结论、必要证据、未完成项和不确定性。内部汇报不另建文件，任务交付物除外。

## 结论与产出

经用户评审确认，已替换用户级 `AGENTS.md` 的旧五条子代理规则，并回读检查；其他主题保持原样。

`config.toml` 未改，`agents/default.toml` 未创建，完整安装尚未完成。CLI 为 `0.154.0-alpha.6.2`，内置目录包含 `gpt-5.6-luna` / `medium`；版本相关字段、TOML 加载和新任务运行仍待验证。新提示词在新任务中使用；若仍缓存旧内容，重启客户端再新建任务。

> 先确定当前生效的 Codex 用户配置目录：优先采用当前 Codex 进程实际使用的 `CODEX_HOME`；未设置时使用当前用户的 `~/.codex`。以下用 `<CODEX_HOME>` 表示该目录，不要把这个占位符原样写进文件，也不要硬编码其他电脑的用户名或绝对路径。
>
> 直接修改目标文件，不创建备份文件。修改前读取现有内容，保留与本次子代理配置无关的模型、账号、权限、插件、工具和提示词设置。不要复制账号凭据，也不要修改 Codex 安装目录。
>
> 先检查目标机器的 Codex 版本及实际支持的配置。以下要求以支持自定义代理文件和 `fork_turns` 的 Codex 为前提。若缺少必要能力或 `gpt-5.6-luna` 不可用，明确说明缺口，不擅自替换模型、不允许继承主代理历史，也不要宣称配置已完整生效。必要时核对 OpenAI 官方说明：
>
> - [子代理与自定义代理配置](https://learn.chatgpt.com/docs/agent-configuration/subagents)
> - [配置字段参考](https://learn.chatgpt.com/docs/config-file/config-reference)
>
> 请完成以下三处修改。
>
> ## 1. 合并修改 `<CODEX_HOME>/config.toml`
>
> 将以下设置合并到现有对应表中，不要直接追加重复的 TOML 表或键。并发上限为 10 个子代理，不包含主代理。
>
> [agents]
> enabled = true
>
> # 最多 10 个并行子代理，此处计数不含主线程
>
> max\_concurrent\_threads\_per\_session = 10
>
> [features.multi\_agent\_v2]
>
> # 保留派发元数据控制；default 模板由 AGENTS.md 指定
>
> hide\_spawn\_agent\_metadata = true
>
> # 不向主代理暴露子代理的模型与推理强度覆盖
>
> expose\_spawn\_agent\_model\_overrides = false
>
> # wait\_agent 可请求的最短等待
>
> min\_wait\_timeout\_ms = 50000
>
> # 单次等待的默认超时；收到结果或用户输入时可提前返回
>
> default\_wait\_timeout\_ms = 120000
> max\_wait\_timeout\_ms = 240000
>
> 以上等待值控制单次等待调用，不是子代理的总运行时限。`features.multi_agent_v2` 的细项属于版本相关设置，必须按目标版本核对；如果某项已改名或不再支持，采用已验证的等效配置，并在结果中说明差异。不要为了保留表面一致而写入无效字段。不要沿用旧教程中“删除整个 `[agents]` 表”的做法；若现有配置用旧字段重复设置同一并发上限，按当前版本迁移到唯一有效的设置位置。
>
> 默认子代理的模型由下面的 `agents/default.toml` 固定；不修改主代理模型，也不增加相互冲突的子代理模型覆盖。
>
> ## 2. 精简 `<CODEX_HOME>/AGENTS.md` 的子代理章节
>
> 若已有“子代理使用”“子代理派发要求”或同义章节，用以下完整章节替换其旧内容及下级小节；若不存在则新增。合并重复的子代理规则，移除与新章节冲突的旧要求，包括不限制修改范围、强制一次性使用、禁止复用或补问等。其他主题的提示词保持原样。
>
> ## 子代理使用
>
> 使用 `default` 通用子代理；何时派发、如何分工由主代理自主决定，并由主代理负责最终整合与验证。
>
> 子代理对主代理的防止上下文腐烂、进行第三方观点提出、无需强推理和大量上下文信息的机械和苦力工作等方面有益处。所以你要在适当的时候自行决定如何调用子代理。默认只读探查、检索和整理证据，隔离探索噪音；只交回精炼结论、必要证据及不确定性。代码设计与实现由主代理负责，这部分不外派。
>
> 你最多可并行使用10个子代理，何时使用使用多少你自行决定。
>
> 调用 `spawn_agent` 时，若工具暴露 `agent_type` 参数，显式传 `agent_type = "default"`；未暴露时省略类型参数，按 `default` 默认角色派生。
>
> - 每次派生必须显式传 `fork_turns = "none"`，不继承主代理历史主代理以获得独立视角；任务说明必须自包含。
> - 子代理工作过程，主代理可自行做其他事情。
> - 通过子代理每轮的最终答复接收结果，不安排通过临时落盘的报告文件传递内部结论。
> - 主代理必须在每次委派的任务说明中明确告知子代理：不得派生、调用或者请求新的子代理。
>
> `default` 是统一承载规则的通用模板，具体职责由主代理在上述边界内决定。角色按 TOML 文件中的 `name = "default"` 注册；自定义同名角色优先于内置默认角色。不要改成其他代理类型来绕过模板中的职责边界、模型和返回规则。
>
> ## 3. 创建或更新 `<CODEX_HOME>/agents/default.toml`
>
> 将该文件完整替换为以下内容。文件名和 `name` 都必须是 `default`；保留其他自定义代理文件。
>
> name = "default"
>
> description = "Read-only exploration and concise evidence gathering; only simple mechanical bulk edits when explicitly delegated. Uses gpt-5.6-luna with medium reasoning."
>
> model = "gpt-5.6-luna"
>
> model\_reasoning\_effort = "medium"
>
> developer\_instructions = """
> 你是主代理派出的探查助手，默认只读探查、检索和整理证据，将探索过程留在子代理上下文中。仅在主代理明确指定时执行规则明确、无需全局上下文或复杂判断的机械批量修改；需要设计决策或复杂实现时交回主代理。
>
> - 第一行只写一个词的状态：complete / partial / blocked。这用于向主代理说明本次完成情况。

> - 仅交回精炼结论、必要证据、未完成项和不确定性；不寒暄，不复述探索过程，不重复任务要求。
> - 确认无法继续时，及时以最终答复交回已完成内容、阻塞原因与未覆盖内容。
> - 不得派生、调用或者请求新的子代理。
>   """
>
> [agents]
> enabled = false
>
> [features]
